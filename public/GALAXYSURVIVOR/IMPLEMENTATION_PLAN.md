# GALAXY SURVIVOR 구현 계획

기준: HTML5 세로형 앱인토스 게임. 각 단계는 앞 단계의 검증을 마친 뒤 진행한다.

| 순서 | 단계 | 완료 기준 | 상태 |
|---|---|---|---|
| 1 | 대기 화면 | 출격·랭킹·강화 진입점, 모바일 화면 | 화면 초안 완료 |
| 2 | 전투 프로토타입 | 드래그 이동, 자동 공격, 적·피격, 종료와 재도전 | 진행 중 |
| 3 | 전투 성장 | 에너지 수집, 레벨업 3지선다, 강화 효과 | 진행 중 |
| 4 | 스테이지와 보스 | 적 패턴, 3분 웨이브, 보스와 승리 | 진행 중 |
| 5 | 결과 및 영구 성장 | 점수 내역, 코인·강화 저장, 일반 모드 적용 | 진행 중 |
| 6 | 경쟁 | 고정 능력치 랭킹 모드, 토스 리더보드 연동 | SDK 설치 및 토스 환경 검증 필요 |
| 7 | 앱인토스 통합 | 공식 SDK 식별, 저장, 종료 확인, 안전영역 및 사운드 수명주기 | 개발자 콘솔 및 SDK 설정 필요 |
| 8 | 검증과 출시 | 실기기 성능·접근성·기록·네트워크·심사 체크리스트 확인 | 미착수 |

현재 로컬 프로토타입의 저장은 브라우저 단위다. 기기 간 기록 유지와 실제 랭킹은 서버 및 앱인토스 사용자 식별 연결 후에만 가능하다. 테스트용 수치는 플레이 검증 후 조정한다.

## 2026-10-29 진행 기록

- 2~5단계의 로컬 프로토타입을 구현했다: 이동·자동 사격·적·피격, 에너지와 강화 선택, 3분 후 보스, 결과 및 브라우저 저장 기반 화력 강화.
- 랭킹 도전은 동일 시작 능력치의 연습 모드다. 실제 랭킹 등록, 주간 집계, 보상, 서버 검증은 아직 구현되지 않았다.
- 현재는 기본 원형 적과 보스만 있고, 기획의 적 4종·탄막·보스 공격 예고와 영구 성장 3종은 미완료다. 점수 세부 내역과 모든 성장 표시도 미완료다.
- JavaScript 구문 검사는 통과했다. 브라우저 화면 및 실기기 플레이 검증은 미완료다.
- 다음 작업: 플레이 검증 후 적 패턴과 보스 공격, 결과 내역과 성장 화면을 완성하고, 서버 및 앱인토스 SDK 통합을 진행한다.

## 토스 리더보드 연동 방향 (2026-10-29)

- 주간 시즌 대신 토스 제공 전체 리더보드 사용. 랭킹 모드의 종료 점수만 제출하고 일반 모드 점수는 제출하지 않는다.
- `toss-entry.js`는 공식 SDK 사용자 식별 성공 시 점수 제출과 리더보드 열기 기능을 연결한다. 브라우저 직접 실행은 연습 모드다.
- 콘솔에서 등록한 appName과 설정 파일을 일치시키고, 리더보드 점수 단위를 점수, 정렬을 높은 점수 우선으로 설정한다. 미니앱 정보 승인과 샌드박스/토스 앱 테스트가 필요하다.
- 네이티브 저장소 및 기기 변경 후 성장 데이터 복원은 아직 구현되지 않았다. 현재 localStorage에만 저장하므로 출시 기준 충족으로 간주하지 않는다.
- 의존성 설치가 네트워크 응답 없이 완료되지 않아 SDK 빌드 및 실제 토스 연동은 검증되지 않았다.


## 필수: 성장 데이터 보존 (출시 차단 항목)

- 브라우저 localStorage와 토스 네이티브 Storage는 기기 내 저장이다. 토스 앱 삭제 및 기기 변경 후 성장을 복원할 수 있는 계정 기반 원격 저장을 구현하기 전에는 출시하지 않는다.
- 서버가 토스 사용자 식별을 안전하게 검증한 뒤 계정에 코인, 강화, 최고 기록을 저장하고 복원한다. 단순히 클라이언트가 주장하는 hash만 인증 수단으로 신뢰하지 않는다. 토스 식별키 인증 코드와 서버 교환 방식의 적용 가능성을 공식 문서로 확인한다.
- 로드 실패를 신규 사용자로 취급하거나 빈 데이터로 덮어쓰지 않는다. 동시 접속·재시도는 버전 관리와 중복 방지로 충돌을 처리한다. 보상은 서버에서 확정하고 저장 성공 후 사용자에게 표시한다.
- 토스 Storage는 선택적 기기 내 캐시로만 사용하며, 계정 복원의 원본으로 취급하지 않는다. 오프라인/네트워크 실패 시 미저장 상태를 알려주고 재시도를 제공한다.
- 검증: 토스 앱 재설치, 동일 계정의 다른 기기, 저장 실패와 재시도, 두 기기 동시 사용, 중복 보상 및 이전 데이터 복원.
- 현재 구현: 로컬 저장 실패 시 강화 성공이나 보상 보관을 잘못 알리지 않도록 수정했다. 원격 저장 및 복원은 미구현이다.
## 전투 프로토타입 업데이트

- 정찰 드론, 빠른 돌진 드론, 조준 탄환을 발사하는 포탑 드론을 추가했다.
- 3분 후 보스가 등장해 발사 예고 후 5방향 탄환을 발사한다. 플레이어 피격 무적과 폭발 효과를 적용했다.
- 자동 공격, 드래그 이동, 에너지 수집, 강화 3지선다와 결과 화면을 사용한다.
- 아직 실기기 밸런스 검증, 오디오, 완성 아트, 서버 저장 및 토스 SDK 실동작 검증은 하지 않았다. 표시된 적과 효과는 프로토타입이다.

## 인게임 난이도와 무기 설계 (프로토타입)

- 0~8초: 정찰 드론으로 조작과 공격을 익힌다. 8초 이후 돌진 드론을 추가하고, 18초 이후 원거리 포탑을 섞는다.
- 적의 체력은 45초마다 증가하며, 출현 간격과 이동 속도는 시간에 따라 점차 빨라진다. 180초에 보스가 등장한다.
- 전투 무기: 전방 분열탄(2단계), 추적 미사일(4단계), 회전 위성(4단계), 전격 파동(4단계). 보조 강화: 연사(5단계), 공격력(5단계), 자석(3단계), 즉시 회복.
- 선택지에 현재/다음/최대 단계를 표시하고 최대 단계에 도달한 항목은 제외한다. 실제 난이도와 무기 수치는 미검증이며 플레이 테스트를 통해 조정해야 한다.

## 폭탄·히든 스킬·파츠 상점 (2026-10-30)
- 폭탄 드롭은 기존 1%를 유지하고 사용 간 8초 재사용 대기시간을 적용한다. 게임 일시정지 중 시간은 흐르지 않는다.
- 히든 스킬 해금 순간 섬광 및 확산 효과, 스킬 공격 발동 순간 별도 색상의 효과가 나타난다.
- 파츠 상점은 코인으로 장갑·엔진 색상을 구매하고 부위별 장착한다. 외형만 바뀌며 획득 코인과 구매 내역은 현재 브라우저에 저장된다.
- 상품 원본 `data/shop.csv`를 수정한 뒤 `node tools/build-shop.cjs`로 `shop-catalog.js`를 재생성한다. 파츠 추가는 기존 부위 및 색상 범위에 한정된다.
- 출시 차단: 기기 간 재화·구매 내역 복원, 서버 인증과 거래 원자성, 토스 실기기 검증은 미완료다. 현재 프로토타입을 실제 유료 상품이나 확정 보상에 사용하지 않는다.

## 다섯 스테이지와 반복 라운드 (2026-10-30)
- 한 출격에서 5개 스테이지를 순차적으로 진행하며, 각 스테이지는 3개 60초 생존 웨이브와 보스전으로 구성된다. 다섯 번째 스테이지 클리어 후 같은 5개 구성을 다음 라운드에서 반복한다.
- 다섯 스테이지는 동일한 기지 배경 자산에 서로 다른 색조·픽셀 구조를 얹은 프로토타입 맵이다. 두 번째 라운드부터 붉은 틴트를 적용한다. 완성된 독립 배경 아트는 아직 없다.
- 적·보스 체력 배율: (1 + (스테이지 - 1) × 0.12) × (1 + (라운드 - 1) × 0.40). 라운드에 따라 방어와 탄환 속도도 일정 상한까지 증가한다.
- 체력·장착 강화·폭탄·획득 코인은 다음 스테이지에서 유지하고, 탄환 및 적은 제거한다. 각 보스 클리어 시 다음 스테이지 또는 보상 수령 후 종료를 선택한다. 중복 클리어 점수 지급은 막는다.
- 자동 검사는 보스 처치 후 1→2→3→4→5→2라운드 1스테이지 전환과 체력·강화·누적 시간 보존, 점수 중복 방지를 확인한다. 직접 실력 플레이 및 2라운드 난이도·맵 시각 검증은 미완료다. 코인·구매 내역의 원격 저장도 미완료다.

## 토스 리더보드 연동 (2026-10-30)
- 공식 웹 SDK 3.9.0을 설치했다. 게임 식별키 조회 후 랭킹 점수 제출 및 토스 순위 화면 열기를 연결했다. 식별키는 콘솔 출력이나 브라우저 저장을 하지 않는다.
- 랭킹 모드 종료 점수만 제출한다. 결과 화면에서 제출 성공·실패를 표시하고 실패 시 다시 시도할 수 있다. 결과 화면과 대기 화면에서 순위 화면을 열 수 있다.
- `npm run build`로 `starfall-shooter.ait` 생성 성공. `vite.config.mjs`가 기존 클래식 스크립트를 dist에 포함한다.
- appName `starfall-shooter`는 임시값이다. 앱인토스 콘솔 등록 ID와 일치시켜 재빌드하고 미니앱 정보 승인, 게임 리더보드 정책 설정 후 샌드박스/토스 앱에서 실기기 테스트해야 한다. 샌드박스 점수는 실제 서비스 랭킹에 반영되지 않는다.
- 자동 검사는 모의 SDK로 제출 실패·재시도·성공, 결과 및 홈에서 열기, 일반 출격 미제출을 확인했다. 실제 토스 점수 전송과 조작 방지, 계정 기반 성장 데이터 복원은 미검증·미완료다.
